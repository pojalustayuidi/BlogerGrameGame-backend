# Игровой API

**Базовый адрес в локальном режиме:** `http://127.0.0.1:8085/api/v1/game`.

Все маршруты в этом документе требуют заголовок `Authorization: Bearer <accessToken>`. Получение и обновление токенов описано в [GUEST_AUTH.md](GUEST_AUTH.md).

> [!IMPORTANT]
> Игровой API работает с **немедленной проверкой каждой буквы**. Старый маршрут проверки всей фразы `/attempts/:id/check` сохранён только как ответ `410 LETTER_VALIDATION_ONLY`. Не используйте его в новом Flutter-клиенте.

## Уровни и попытки

| Метод | Путь | Назначение |
|:--|:--|:--|
| `GET` | `/categories` | Категории со счётчиками доступных уровней |
| `GET` | `/levels?category=streamers` | Метаданные уровней, **без текста цитаты и автора** |
| `POST` | `/levels/:id/attempts` | Создать или продолжить незавершённую попытку; тело `{}` |
| `GET` | `/attempts/:id` | Текущее поле, сохранённые буквы, блокнот, ошибки, статус и бонус |

Для каталога локальных черновиков нужен `LOCAL_DRAFT_PREVIEW=1`. В остальных случаях отображаются только опубликованные уровни.

### Формат поля

```json
{
  "position": 5,
  "type": "letter",
  "number": 17,
  "given": null,
  "letter": null
}
```

Разделители и пробелы не требуют букв:

```json
{ "position": 6, "type": "separator", "value": " " }
```

`position` — индекс символа в цитате, считая с нуля, **включая** пробелы и знаки препинания; `number` — число, соответствующее кириллической букве в данной попытке. Пример выше иллюстративный, не ответ реального уровня. Исходная подсказка отражается в `given`, подтверждённая буква — в `letter`; у платной подсказки добавляется `hinted: true`.

## Ввод буквы

```http
PATCH /api/v1/game/attempts/:id/cells/:position
Content-Type: application/json
Authorization: Bearer <accessToken>

{
  "letter": "В",
  "requestId": "e22a8f35-c6f5-47c3-9dd7-25d94fd5e57a"
}
```

Ответ содержит, в зависимости от результата, `correct`, `triesRemaining`, `mistakes`, `lostLife`, `solved`, а также `wallet` при изменении ресурсов и данные бонуса при победе.

**Условия:**

- Буква должна быть одной кириллической буквой, поддерживается `Ё`; нижний регистр нормализуется.
- Правильная буква закрепляется **только** в запрошенной клетке. Другая клетка с тем же числом остаётся пустой.
- Неправильная буква не сохраняется, но расходует одну из трёх попыток. Каждая третья ошибка — минус жизнь.
- При нуле жизней сервер отвечает `409 NO_LIVES`.
- Закреплённые и открытые подсказкой клетки нельзя переписывать.
- После последней правильно введённой буквы ответ сообщает `solved: true`, начисление за уровень и `bonusOptions`.

### Зачем `requestId`

**Новый UUID для каждого нового нажатия** на игровую клавиатуру. Если запрос повторяется после сетевого сбоя, повторите **тот же UUID** с теми же `position` и `letter`. Сервер вернёт сохранённый результат, не расходуя дополнительную попытку. Изменённые параметры с прежним UUID приводят к `409 REQUEST_ID_CONFLICT`.

## Блокнот и подсказки

| Метод | Путь | Тело |
|:--|:--|:--|
| `PUT` | `/attempts/:id/notes/:number` | `{"letter":"А","comment":"вероятно гласная"}` |
| `POST` | `/attempts/:id/hints/reveal` | `{"position":7}` |

Блокнот **не заполняет клетки и не проверяет буквы**. Подсказка расходует доступную подсказку и открывает **одну физическую клетку**. Повторное открытие той же клетки не списывает вторую подсказку. При нуле жизней новые подсказки заблокированы.

## Завершение и бонус

После заполнения всех клеток корректными буквами попытка получает статус `solved`. Текст и автор ещё не раскрываются в обычном поле, пока не завершён необязательный бонус:

```http
POST /api/v1/game/attempts/:id/bonus
Content-Type: application/json
Authorization: Bearer <accessToken>

{ "guessedCreatorId": "<uuid-из-bonusOptions>" }
```

Отправьте `null`, чтобы пропустить вопрос. Ответ возможен **один раз**, после чего API возвращает исходную цитату, автора и сведения об источнике, если они есть. Ссылки непроверенных черновых источников не следует считать разрешением на встраивание видео.

## Монеты, жизни и магазин

| Метод | Путь | Описание |
|:--|:--|:--|
| `GET` | `/wallet` | `coins`, `lives`, `hints`, лимиты и `nextLifeAt` |
| `GET` | `/wallet/history` | Последние операции экономики |
| `GET` | `/shop` | Предложения и серверные цены |
| `POST` | `/shop/purchases` | `{"sku":"life_1","requestId":"<uuid>"}` |

Нельзя передавать клиентскую цену или количество ресурса вместо серверного SKU. Подробности — [ECONOMY.md](ECONOMY.md).

## Типичные коды ошибок

| Код HTTP | Пример `error` | Значение |
|:--|:--|:--|
| `400` | `INVALID_CELL_REQUEST`, `INVALID_LETTER_REQUEST` | Неверная форма запроса |
| `401` | `UNAUTHORIZED` | Отсутствует или истёк токен |
| `404` | `ATTEMPT_NOT_FOUND` | Попытка отсутствует или не принадлежит игроку |
| `409` | `NO_LIVES`, `CELL_ALREADY_CORRECT`, `REQUEST_ID_CONFLICT` | Игровой конфликт |
| `410` | `LETTER_VALIDATION_ONLY` | Прежняя проверка всей фразы отключена |

**Важно:** этот API локальный. Контракт основан на действующем коде ветки пятого этапа; публичный OpenAPI-файл пока не поддерживается. Старую ссылку на SwaggerHub не следует считать актуальной спецификацией.
