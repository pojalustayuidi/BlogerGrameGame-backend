# Экономика 1.1 — проверка по букве, жизни и магазин

Это локальный тестовый баланс. Сервер управляет состоянием; Flutter не может самостоятельно начислять монеты, жизни и подсказки.

## Правила

| Событие | Результат |
|---|---|
| Старт гостя | 30 монет, 5 жизней, 2 подсказки |
| Правильная буква | Заполняет лишь выбранную клетку, попытки не расходуются |
| Неправильная буква | Не заполняет клетку; минус 1 из 3 попыток |
| 3-я ошибка (также 6-я, 9-я…) | Минус одна жизнь, снова 3 попытки |
| Жизни закончились | Ввод и подсказки блокируются до восстановления/покупки |
| Восстановление | 1 жизнь каждые 30 минут, максимум 5 |
| Первая победа | 20 / 30 / 40 / 55 монет за easy / normal / hard / expert |
| Победа без ошибок и платных подсказок | +5 монет |
| Угадывание автора | +10 монет, один раз |
| Повторное завершение | 0 наград |

Начальные открытые буквы не мешают идеальной победе. Ввод не может изменить уже подтверждённую клетку. Подсказка открывает **ровно одну физическую клетку**, а не все клетки с одинаковым шифровальным номером.

## Магазин за монеты

| SKU | Награда | Цена в монетах |
|---|---|---|
| `life_1` | 1 жизнь | 50 |
| `life_3` | 3 жизни | 120 |
| `hint_1` | 1 подсказка | 45 |
| `hint_3` | 3 подсказки | 120 |

Нельзя купить больше максимума (5 жизней, 20 подсказок) или потратить несуществующие монеты. Монеты ограничены 1 000 000.

**Реклама за жизнь и покупки за настоящие деньги ещё не подключены.** Их нельзя реализовывать как незащищённый запрос от клиента «выдай мне жизнь». Потребуются SDK Flutter, проверка событий на сервере, идемпотентность и учёт платформы распространения.

## API

Везде, где указан игровой API, нужен `Authorization: Bearer <accessToken>`.

- `GET /api/v1/game/wallet` — серверный баланс `{coins,lives,hints,maxLives,maxHints,lifeRegenMinutes,nextLifeAt}`.
- `GET /api/v1/game/wallet/history` — последние 30 операций, включая `wrong_letter` при потере жизни.
- `GET /api/v1/game/shop` — реальные серверные предложения, нельзя прислать клиентскую цену.
- `POST /api/v1/game/shop/purchases` — `{"sku":"life_1","requestId":"uuid"}`; повтор ID не списывает второй раз.
- `PATCH /api/v1/game/attempts/:id/cells/:position` — **`{"letter":"В","requestId":"uuid"}`**. Ответ: `correct`, `triesRemaining`, `mistakes`, `lostLife`, `solved`, `wallet` при необходимости. Неверная буква не записывается.
- `POST /api/v1/game/attempts/:id/hints/reveal` — `{"position":5}`, раскрывает одну клетку, повторное нажатие не списывает подсказку.
- `POST /api/v1/game/attempts/:id/bonus` — единственный шанс выбрать автора, +10 за правильный.
- `POST /api/v1/game/attempts/:id/check` — **HTTP 410**, удалённый игровой сценарий.

На старте и восстановлении попытки `triesRemaining` показывает оставшиеся попытки до потери следующей жизни. При `NO_LIVES` UI показывает таймер `nextLifeAt`, кнопку покупки за монеты и в будущем рекламу/платные покупки.

## Безопасность и транзакции

- Все изменения делаются в PostgreSQL-транзакции с блокировкой конкретной попытки `FOR UPDATE OF a` и игрока `FOR UPDATE`.
- `puzzle_letter_requests` хранит ответы на каждый `requestId`. Сетевые повторы не расходуют лишние попытки, даже после победы.
- `economy_ledger` защищён от повторных наград уникальным `(player_id,event_key)`.
- `puzzle_attempts.mistakes` хранит **все неверные отдельные буквы**, а попытки вычисляются по `3 - mistakes % 3`. Старые завершённые попытки не сбрасываются.
- Миграция `005_letter_attempts.sql` добавляется после 004; предыдущие файлы миграций **не редактируются**.
- Нет публикации черновых цитат и нет настоящих покупок или рекламных SDK в этой версии.
