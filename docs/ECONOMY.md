# Игровой баланс и экономика

Экономика хранится на сервере: Flutter показывает состояние, но **не решает**, сколько монет начислить, сколько стоит покупка и какая буква правильная.

## Текущие правила (локальный баланс 1.1)

| Событие | Эффект |
|:--|:--|
| Создание гостя | **30 монет, 5 жизней, 2 подсказки** |
| Верная буква | Закрепить конкретную клетку, без штрафа |
| Неверная буква | −1 попытка; неверная буква не сохраняется |
| Каждая третья неверная буква | −1 жизнь, снова 3 попытки |
| Нет жизней | Ввод и подсказки недоступны до восстановления/покупки |
| Восстановление жизней | +1 каждые **30 минут**, максимум 5 |
| Первая победа | `easy` +20 / `normal` +30 / `hard` +40 / `expert` +55 монет |
| Победа без ошибок и платных подсказок | Ещё +5 монет |
| Верно угадан автор | +10 монет один раз |
| Повторная победа | Повторных наград нет |

Исходные автоматически открытые буквы не мешают получить бонус за безупречное прохождение. Жизни ограничены пятью, подсказки — двадцатью, монеты — одним миллионом.

## Магазин за монеты

| SKU | Что выдаёт | Цена |
|:--|:--|--:|
| `life_1` | 1 жизнь | 50 монет |
| `life_3` | 3 жизни | 120 монет |
| `hint_1` | 1 подсказка | 45 монет |
| `hint_3` | 3 подсказки | 120 монет |

Покупка отклоняется при нехватке монет и при превышении лимита ресурса. Цена определяется только сервером; клиент передаёт SKU и `requestId`.

## Гарантии корректности

- Операции ресурса выполняются в транзакциях с блокировками строк игрока/попытки.
- `economy_ledger` сохраняет начисления и списания; уникальный ключ события предотвращает повторную выдачу наград.
- `puzzle_letter_requests` обеспечивает безопасный повтор сетевого запроса: одна ошибка не может потратить несколько попыток при ретрае.
- Подсказка записывается для `(attempt_id, cell_position)` и не открывает повторяющиеся номера автоматически.
- Восстановление жизней рассчитывается по времени PostgreSQL при обращении к API, без постоянно работающего фонового таймера.

## Эндпоинты

```text
GET  /api/v1/game/wallet
GET  /api/v1/game/wallet/history
GET  /api/v1/game/shop
POST /api/v1/game/shop/purchases
POST /api/v1/game/attempts/:id/hints/reveal
```

Состояние после потери жизни возвращается также в ответе на ввод буквы. Клиент должен обновлять экран по **серверному** балансу и `nextLifeAt`, а не вычислять ресурсы только локально.

## Реклама и настоящие платежи

**Пока не реализованы.** Планируется добровольная rewarded-реклама за жизнь и покупки через SDK магазина приложения. Внешняя рекламная сеть должна подтверждать награду на сервере, а платежи — проверяться по данным платёжной платформы. Нельзя принимать произвольный запрос Flutter «выдай жизнь».

Баланс можно менять после тестирования на телефоне; текущие значения — рабочая исходная версия, а не окончательные цены релиза.
