# BlogerGrame — Backend

**Игровой сервер для криптограмм по цитатам блогеров, стримеров и тиктокеров.**  
Игрок расшифровывает фразу, управляет попытками и подсказками, а после победы угадывает автора.

> [!IMPORTANT]
> **Это локальный backend для разработки и тестирования, не публичный сервер.** Приложение привязано к `127.0.0.1`; публикация в интернете, рекламные награды и платежи за реальные деньги пока не реализованы.

## Что уже работает

| Модуль | Реализация |
|:--|:--|
| **Игроки и авторизация** | Гостевой вход без регистрации, access/refresh-токены, обновление и выход |
| **Криптограммы** | Случайное соответствие букв и чисел, сохранённая попытка, отдельный ввод каждой клетки |
| **Проверка букв** | Правильная буква фиксируется; неверная расходует попытку, но не записывается |
| **Жизни и подсказки** | 3 ошибки = −1 жизнь; 5 жизней максимум; +1 жизнь каждые 30 минут; подсказка открывает одну клетку |
| **Экономика** | Монеты за первый проход, бонус за автора, магазин за монеты, журнал операций |
| **Каталог** | 42 **черновые** цитаты в трёх категориях для локального тестирования |
| **Хранилище** | PostgreSQL, последовательные миграции, резервные копии, тесты с реальной БД |

## Как устроена игра

1. Игрок запускает уровень и получает поле с цифрами вместо букв. Каждой **уникальной букве** назначается случайное число в пределах попытки.
2. Одинаковые числа подсказывают одинаковую букву, **но клетки заполняются только вручную по одной**. Автозаполнения нет.
3. Сервер сразу проверяет введённую букву. Верная закрепляется в выбранной клетке, неверная уменьшает запас попыток. Каждая третья ошибка расходует жизнь.
4. При заполнении последней клетки уровень завершается автоматически, награда начисляется только один раз.
5. После решения открывается необязательный бонус **«Кто это сказал?»**. Автор и исходный текст не показываются раньше времени.

**Блокнот** помогает записывать гипотезы вида «число 7 = В», не подставляя их в поле.

## Технологии и структура

- **Node.js 20+**, **Express 5** — HTTP API и бизнес-логика.
- **PostgreSQL 17** (`pg`) — игроки, попытки, цитаты и история экономики.
- **Docker Compose** — локальная база без отдельной ручной установки PostgreSQL.
- **Node.js Test Runner**, интеграционные smoke-тесты и **GitHub Actions**.

```text
index.js               HTTP-приложение и подключение маршрутов
routes/                auth / game / защищённый admin
services/              правила игровых операций и транзакции
lib/                   проверка конфигурации, токены, генератор шифра, экономика
db/migrations/         версионированные SQL-миграции
content/               черновой каталог цитат
scripts/               миграции, импорт, бэкапы, проверки
tests/                 модульные и контрактные тесты
docs/                  техническая документация
```

## Быстрый старт

Нужны **Node.js 20+**, npm, **Docker Desktop** и PowerShell (инструкции ниже рассчитаны на Windows).

```powershell
# 1. Клонируем репозиторий
git clone https://github.com/pojalustayuidi/BlogerGrameGame-backend.git
cd BlogerGrameGame-backend

# 2. Создаём локальную конфигурацию, поднимаем БД и проверяем Node.js
powershell -ExecutionPolicy Bypass -File .\scripts\setup-local.ps1

# 3. Применяем все миграции и добавляем категории
npm run db:migrate
npm run db:seed

# 4. Импортируем черновой каталог для локальной проверки
npm run content:import-drafts

# 5. Запускаем backend
npm run dev
```

По умолчанию API работает по адресу **`http://127.0.0.1:8085`**, PostgreSQL слушает `127.0.0.1:5433`.

После первого запуска проверьте `http://127.0.0.1:8085/health`.

> [!NOTE]
> `setup-local.ps1` создаёт `.env` только если его ещё нет, и не перезаписывает существующую конфигурацию. В новом окружении следует задать собственный пароль PostgreSQL до инициализации постоянного тома. Для показа **неопубликованных** уровней установите `LOCAL_DRAFT_PREVIEW=1` в локальном `.env` и перезапустите сервер.

Подробные инструкции для первого запуска, повторного запуска и типичных проблем: **[Локальная разработка](docs/GETTING_STARTED.md)**.

## Проверка проекта

```powershell
npm test                     # Модульные и контрактные тесты
npm run db:migrate           # Повторный вызов безопасен
npm run db:smoke             # Структура PostgreSQL
npm run auth:smoke           # Гостевой вход и ротация токенов
npm run game:smoke           # Реальное прохождение криптограммы
npm run economy:smoke        # Попытки, жизни, магазин и награды
npm run db:status            # Состав и наполнение базы
npm audit                    # Проверка зависимостей
```

Интеграционные тесты создают временные данные и очищают их после выполнения. Перед любыми изменениями схемы рекомендуется сделать резервную копию.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\backup-local.ps1
```

Подробнее: [Тестирование](docs/TESTING.md).

## API

Все игровые запросы, кроме `POST /api/v1/auth/guest`, требуют заголовок `Authorization: Bearer <accessToken>`.

| Область | Примеры маршрутов |
|:--|:--|
| Авторизация | `POST /api/v1/auth/guest`, `GET /api/v1/auth/me`, `POST /api/v1/auth/refresh` |
| Уровни | `GET /api/v1/game/categories`, `GET /api/v1/game/levels` |
| Попытки | `POST /api/v1/game/levels/:id/attempts`, `GET /api/v1/game/attempts/:id` |
| Буквы | `PATCH /api/v1/game/attempts/:id/cells/:position` |
| Подсказки и бонус | `POST /api/v1/game/attempts/:id/hints/reveal`, `POST /api/v1/game/attempts/:id/bonus` |
| Кошелёк и магазин | `GET /api/v1/game/wallet`, `GET /api/v1/game/shop`, `POST /api/v1/game/shop/purchases` |

**Каждый ввод буквы требует уникальный `requestId` (UUID).** При сетевом повторе клиент отправляет тот же ID, чтобы попытка не списалась дважды.

Полное описание: [Игровой API](docs/GAME_API.md) · [Гостевой вход](docs/GUEST_AUTH.md) · [Экономика](docs/ECONOMY.md).
